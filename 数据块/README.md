# 数据块 — MiniNAS 存档（部分）

NAS 关之前抢救出来的一点东西。**不是完整备份**，是能捞出来的部分。

| | |
|---|---|
| 索引声明 | 6.1 GB（NAS 上曾经有过的全部内容） |
| 实际打包 | 约 456 MB（357 个数据块） |
| 能完整还原 | 358 个文件 / 约 466 MB |
| 缺失 | 443 个文件的数据块没抢救出来 |

大部分照片没了，这是没办法的事。能还原的那 358 个（329 张图 + 视频 + 文档）我逐个验过，都能正常打开。

## 下载

数据包太大，不进 git 仓库，放在 Release 里：

**https://github.com/ciallo0721-cmd/nas-shutdown/releases**

下载 `all.zip`，解压得到：

```
all/
  C/NAS/index.json      ← 索引（谁叫什么、多大、由哪几块拼成）
  C/NAS/nas  nasx ...   ← 数据块
  D/NAS/nas  nas1 ...
  E的NAS/nas9 ...
```

磁盘上你看到的就是一堆 `nasN`，看不到任何一张照片——因为 NAS 把每个文件切块改名存了。

## 还原

把 `nasdat.py` 和 `all/` 放在同一层，然后：

```bash
python nasdat.py info                     # 先看一眼：多少能还原、多少缺
python nasdat.py check                    # 逐条核对，列清哪些能还原
python nasdat.py extract -o 还原            # 全部还原到 ./还原
python nasdat.py extract -o 还原 --only 塔菲   # 只捞某个目录
```

只需要 Python 3.8+，**不需要装任何第三方库**。

跑完会告诉你成功几个、失败几个、每个失败的原因。缺块的文件默认跳过，不会给你生成半张坏图。

### 目录结构完全对不上？

加 `--data` 手动指定：

```bash
python nasdat.py extract --data D:\nas\all -o D:\还原
```

## 块格式（给想自己写解析的人）

源码 `nas_server.py` 开头写了一句：

```
存储格式: [n"文件名"]<二进制内容>[ed]
```

实际每一块都套了这层壳：

```
首块:   [n"文件相对路径"]  +  内容  +  [ed]
续块:                      内容  +  [ed]
```

- `[n"..."]` 只有首块有，里面是 JSON 转义过的相对路径（`塔菲/xxx.jpeg` 这种，带目录）
- `[ed]` 是 4 字节尾标，**每一块**都有
- 块名按 `nas`、`nas1`、`nas2`… 递增；老版本是个 bug，会用 `nasx`、`nasxx`、`nasxxx` 无限加 x

所以还原就是：剥头 → 剥尾 → 按索引顺序拼接 → 按声明大小截断。

`nasdat.py` 里有完整实现，`iter_chunk_payload()` 就是干这个的，流式读，95MB 的视频也不会爆内存。
